# Adding a feature to core-service

Worked through **`blog-category`**, which is the cleanest complete vertical slice in the codebase:
full CRUD, its own DI module, its own domain exceptions, two value objects (one with real
invariants), and a spec for every use case.

> **Copy `blog-category`, not `department`.** `department` is a near-identical CRUD but is indented
> with 4 spaces against a 2-space `.prettierrc`, has zero tests, shares another feature's DI module,
> and its controller injects a use case from a different feature. Also ignore
> `src/presentation/modules/upload/` — pre-hexagonal layout.

Existing docs worth reading alongside this one:
`elearning-core-service/.claude/skills/enforce-hexagonal-architecture/SKILL.md` (the authoritative
rules) and `elearning-core-service/docs/BACKEND_DEVELOPER_HANDOVER.md` §3.

## Step 1 — Domain: the entity

Pure TypeScript. No `@nestjs/*`, no `drizzle-orm`, no `class-validator`.

```ts
// src/domain/blog/entities/blog-category.entity.ts
export class BlogCategory {
  private readonly _id: BlogCategoryId;
  private _name: string;
  private _iconColor: string | null;
  private _displayNames: BlogCategoryDisplayNames;
  private readonly _createdAt: Date;
  private _updatedAt: Date;

  private constructor(props: { /* every field */ }) { /* assign */ }

  /** NEW entity — generates its own ID and timestamps. */
  static create(props: {
    name: string;
    iconColor?: string | null;
    displayNames: BlogCategoryDisplayNames;
  }): BlogCategory {
    const now = new Date();
    return new BlogCategory({
      id: BlogCategoryId.generate(),
      name: props.name.trim(),
      iconColor: props.iconColor ?? null,
      displayNames: props.displayNames,
      createdAt: now,
      updatedAt: now,
    });
  }

  /** LOADING from the database — repository adapters must use this. */
  static reconstitute(props: { /* every field, all required */ }): BlogCategory {
    return new BlogCategory(props);
  }

  update(params: { name?: string; iconColor?: string | null; displayNames?: BlogCategoryDisplayNames }): void {
    if (params.name !== undefined) this._name = params.name.trim();
    if (params.iconColor !== undefined) this._iconColor = params.iconColor;
    if (params.displayNames !== undefined) this._displayNames = params.displayNames;
    this._updatedAt = new Date();
  }

  get id(): BlogCategoryId { return this._id; }
  get name(): string { return this._name; }
  // … getters only, no setters
}
```

The two factories are the point. **`create()` mints a new identity; `reconstitute()` restores an
existing one.** Using `create()` in a repository would generate a fresh UUID on every read.

## Step 2 — Domain: value objects

A VO validates its own invariants in `create()` and is otherwise immutable:

```ts
// src/domain/blog/value-objects/blog-category-id.vo.ts
export class BlogCategoryId {
  private readonly _value: string;
  private constructor(value: string) { this._value = value; }

  static create(value: string): BlogCategoryId {
    const normalized = value.trim().toLowerCase();
    if (!this.isValidUUID(normalized)) {
      throw new Error(`Invalid BlogCategoryId UUID: ${value}`);
    }
    return new BlogCategoryId(normalized);
  }

  static generate(): BlogCategoryId {
    return new BlogCategoryId(randomUUID());
  }

  getValue(): string { return this._value; }
  equals(other: BlogCategoryId | null | undefined): boolean {
    if (!other) return false;
    return this._value === other._value;
  }
  toString(): string { return this._value; }
}
```

`getValue()` is how the VO reaches the database. Persisting the object itself writes `[object Object]`.

## Step 3 — Domain: the repository port

The interface **and** its DI token live in the same file. This is the current convention — prefer it
over adding to the legacy `shared/constants/tokens.ts`.

```ts
// src/domain/blog/ports/repositories/blog-category.repository.port.ts
export interface FindAllBlogCategoriesParams {
  page: number;
  limit: number;
  name?: string;
}

export interface IBlogCategoryRepositoryPort {
  save(category: BlogCategory): Promise<void>;          // insert AND update
  findById(id: BlogCategoryId): Promise<BlogCategory | null>;   // null on miss, never throws
  findByName(name: string): Promise<BlogCategory | null>;
  findByIds(ids: BlogCategoryId[]): Promise<BlogCategory[]>;
  delete(id: BlogCategoryId): Promise<void>;
  countPostsForCategory(id: BlogCategoryId): Promise<number>;
  findAll(params: FindAllBlogCategoriesParams): Promise<{ items: BlogCategory[]; total: number }>;
}

export const BLOG_CATEGORY_REPOSITORY = Symbol('BLOG_CATEGORY_REPOSITORY');
```

Note `save()` is upsert-shaped — one method for create and update — and `findById` returns `null`
rather than throwing.

```ts
// src/domain/shared/exceptions/domain-exceptions.ts
export abstract class DomainException extends Error {
  readonly httpStatus: number;
  readonly metadata?: Record<string, any>;
  constructor(message: string, httpStatus: number, metadata?: Record<string, any>) {
    super(message);
    this.name = this.constructor.name;
    this.httpStatus = httpStatus;
    this.metadata = metadata;
  }
}
```

Importing `HttpStatus` here is a grandfathered exception to the purity rule; the controller still
maps domain exceptions to HTTP exceptions explicitly.

## Step 5 — Application: the use case

Three files per mutation: input carrier, output carrier, orchestrator.

```ts
// create-blog-category.command.ts
export class CreateBlogCategoryCommand {
  constructor(
    public readonly name: string,
    public readonly iconColor: string | null,
    public readonly displayNames: Record<string, string>,
  ) {}
}
```

```ts
// create-blog-category.result.ts
export class CreateBlogCategoryResult {
  constructor(
    public readonly id: string,
    public readonly name: string,
    public readonly iconColor: string | null,
    public readonly displayNames: Record<string, string>,
    public readonly createdAt: Date,
    public readonly updatedAt: Date,
  ) {}

  static fromEntity(entity: BlogCategory): CreateBlogCategoryResult {
    return new CreateBlogCategoryResult(
      entity.id.getValue(),                              // VO → primitive at the boundary
      entity.name,
      entity.iconColor,
      entity.displayNames as Record<string, string>,
      entity.createdAt,
      entity.updatedAt,
    );
  }
}
```

```ts
// create-blog-category.use-case.ts
@Injectable()
export class CreateBlogCategoryUseCase {
  constructor(
    @Inject(BLOG_CATEGORY_REPOSITORY)
    private readonly repository: IBlogCategoryRepositoryPort,   // the PORT, never the adapter
  ) {}

  async execute(command: CreateBlogCategoryCommand): Promise<CreateBlogCategoryResult> {
    const existing = await this.repository.findByName(command.name.trim());
    if (existing) {
      throw new BlogCategoryAlreadyExistsException(command.name);
    }

    const displayNames = BlogCategoryDisplayNames.create(command.displayNames);
    const category = BlogCategory.create({
      name: command.name,
      iconColor: command.iconColor,
      displayNames,
    });

    await this.repository.save(category);
    return CreateBlogCategoryResult.fromEntity(category);
  }
}
```

The shape is always **Load → Execute → Save → Return**. Use cases hold no state, contain no SQL, and
inject ports only. There is no `CommandBus` — controllers call `execute()` directly.

For a list, the result owns the pagination maths:

```ts
// list-blog-categories.result.ts
export class BlogCategoryPaginationMetadata {
  constructor(

    public readonly page: number,
    public readonly limit: number,
    public readonly totalPages: number,
  ) {}
}

static fromEntitiesWithPagination(categories, total, page, limit): ListBlogCategoriesResult {
  const totalPages = Math.ceil(total / limit);
  return new ListBlogCategoriesResult(
```

## Step 7 — Infrastructure: the repository adapter

```ts
// src/infrastructure/persistence/drizzle/repositories/blog-category.repository.adapter.ts
@Injectable()
export class DrizzleBlogCategoryRepositoryAdapter implements IBlogCategoryRepositoryPort {
  constructor(@Inject(DRIZZLE) private readonly drizzle: NodePgDatabase<any>) {}

  async save(category: BlogCategory): Promise<void> {
    await this.drizzle
      .insert(blogCategories)
      .values({
        id: category.id.getValue(),                          // VO → primitive
        name: category.name,
        iconColor: category.iconColor,
        displayNames: JSON.stringify(category.displayNames),
        createdAt: category.createdAt,
        updatedAt: category.updatedAt,
      })
      .onConflictDoUpdate({
        target: blogCategories.id,
        set: { name: category.name, /* … */ updatedAt: category.updatedAt },
      });
  }

  private mapToDomain(row: typeof blogCategories.$inferSelect): BlogCategory {
    const displayNamesRaw: Record<string, string> =
      typeof row.displayNames === 'string'
        ? JSON.parse(row.displayNames)
        : (row.displayNames as Record<string, string>);

    return BlogCategory.reconstitute({          // ⚠ NEVER .create() — would mint a new ID
      id: BlogCategoryId.create(row.id),
      name: row.name,
      iconColor: row.iconColor ?? null,
      displayNames: BlogCategoryDisplayNames.create(displayNamesRaw),
      createdAt: row.createdAt!,
      updatedAt: row.updatedAt!,
    });
  }
}

// Re-export the token so the DI module can import from one place
export { BLOG_CATEGORY_REPOSITORY };
```

Paginated reads are a `count` then a paged `select`:

```ts
const [{ total }] = await this.drizzle
  .select({ total: sql<number>`count(*)::int` })
  .from(blogCategories)
  .where(where);

const rows = await this.drizzle
  .select()
  .from(blogCategories)
  .where(where)
  .orderBy(desc(blogCategories.createdAt))
  .limit(limit)
  .offset(offset);
```

> **`mapToDomain` must return the entity directly.** A real production bug came from a repository
> that round-tripped through a DTO and cast back: `id` became a plain string and
> `book.id.getValue is not a function` blew up at runtime.

## Step 9 — Presentation: DTOs

This is the only layer where `class-validator` is allowed.

```ts
// dtos/create-blog-category-http.dto.ts
export class CreateBlogCategoryHttpDto {
  @ApiProperty({ example: 'Technology' })
  @IsString()
  @IsNotEmpty()
  name: string;

  @ApiPropertyOptional({
    example: '#FF5733',
    description: 'Icon color as HEX code (e.g. #FF5733)',
  })
  @IsOptional()
  @IsString()
  @Matches(/^#[0-9A-Fa-f]{6}$/, {
    message: 'iconColor must be a valid HEX color code (e.g. #FF5733)',
  })
  iconColor?: string | null;

  @ApiProperty({
    example: { vn: 'Công nghệ', en: 'Technology' },
    description: 'Display names per market. At least one market required.',
  })
  @IsObject()
  displayNames: Record<string, string>;
}
```

The list DTO — `@Type(() => Number)` is **required**, because query strings arrive as strings:

```ts
// dtos/list-blog-categories-http.dto.ts
export class ListBlogCategoriesHttpDto {
  @ApiPropertyOptional({ default: 1, minimum: 1 })
  @IsOptional()
  @Type(() => Number)
  @IsInt()
  @Min(1)
  page?: number = 1;

  @ApiPropertyOptional({ default: 20, minimum: 1, maximum: 100 })
  @IsOptional()
  @Type(() => Number)
  @IsInt()
  @Min(1)
  @Max(100)
  limit?: number = 20;
}
```

> **Declare every field a client will send.** `forbidNonWhitelisted: true` turns one undeclared key
> into a hard `400`.

## Step 10 — Presentation: the controller

Thin. It builds a command, calls `execute()`, and maps domain exceptions to HTTP exceptions.

```ts
// blog-category.controller.ts
@ApiTags('Blog Categories')
@Controller('blog-categories')
export class BlogCategoryController {
  constructor(
    private readonly createUseCase: CreateBlogCategoryUseCase,
    private readonly updateUseCase: UpdateBlogCategoryUseCase,
    private readonly deleteUseCase: DeleteBlogCategoryUseCase,
    private readonly getUseCase: GetBlogCategoryUseCase,
    private readonly listUseCase: ListBlogCategoriesUseCase,
  ) {}

  @Post()
  @HttpCode(HttpStatus.CREATED)
  @Permissions(BLOG_CATEGORY_CREATE)
  @ApiBearerAuth('JWT-auth')
  @ApiOperation({ summary: 'Create a new blog category' })
  @ApiResponse({ status: HttpStatus.CREATED, description: 'Category created' })
  @ApiResponse({ status: HttpStatus.CONFLICT, description: 'Category name already exists' })
  async createCategory(
    @Body() dto: CreateBlogCategoryHttpDto,
    @I18n() i18n: I18nContext<I18nTranslations>,
  ) {
    try {
      const result = await this.createUseCase.execute(
        new CreateBlogCategoryCommand(dto.name, dto.iconColor ?? null, dto.displayNames),
      );
      return {
        message: i18n.t('common.blogCategory.create_success'),
        data: result,
      };
    } catch (e) {
      if (e instanceof BlogCategoryAlreadyExistsException) throw new ConflictException(e.message);
      throw e;
    }
  }
```

The public read variant:

```ts
  @Public()
  @Get('list')
  @HttpCode(HttpStatus.OK)
  @ApiOperation({ summary: 'List blog categories with pagination' })
  @ApiResponse({ status: HttpStatus.OK, description: 'Categories retrieved' })
  async listCategories(@Query() dto: ListBlogCategoriesHttpDto) {
    return this.listUseCase.execute(
      new ListBlogCategoriesQuery(dto.page ?? 1, dto.limit ?? 20, dto.name),
    );
  }
```

Three things to copy:

- **`@Public()` or `@Permissions(...)` on every route.** No exceptions. See Step 11.
- **Re-apply pagination defaults with `??`** even though the DTO declares them, because DTO defaults
  only apply when the key is absent.
- **`return { message, data: result }` produces a nested `data.data`.** This is the existing style
  here; know it and tell whoever writes the client. See
  [`02-api-contract.md`](02-api-contract.md#the-datadata-trap).

## Step 11 — The four registrations that fail silently

This is the step people skip. Each failure mode below is real and none of them produce a helpful
error.

### 11a. `src/app.module.ts` — twice

```ts
// 1) the module
imports: [
  // …
  BlogCategoryPresentationModule,
]

// 2) the controller, in the middleware list
configure(consumer: MiddlewareConsumer) {
  consumer
    .apply(JwtDecodeMiddleware, GetMarketMiddleware)
    .forRoutes(
      // …
      BlogCategoryController,
    );
}
```

> **Forgetting the second one is the classic bug.** The routes respond, so it looks wired. But
> `JwtDecodeMiddleware` never runs, so `req.user` is `undefined` and **every permissioned route
> returns `401`**; and `GetMarketMiddleware` never runs, so `req.market` is `undefined` and
> market-scoped queries fall back or crash.
>
> There is a regression test for exactly this class of mistake in `src/app.module.spec.ts`.
>
> Some controllers are **deliberately absent** — webhooks, `integration/`, and upload/ai-storage
> authenticate by API key instead of JWT.

### 11b. `src/infrastructure/databases/schemas/index.ts` — twice

```ts
import * as blogCategories from './blog-category.schema';   // 1
// …
export default {
  // …
  blogCategories,                                           // 2
};
```

> **Migrations generate correctly even if you forget**, because `drizzle.config.ts` globs
> `*.schema.ts` directly. But `drizzleProvider` passes `schemas.default` as the relational schema,
> so **relational queries for your table break at runtime** with no build-time warning.

### 11c. Permissions — constant, seed, run

```ts
// src/shared/constants/permissions.ts
export const BLOG_CATEGORY_CREATE = 'blog-category:create';
export const BLOG_CATEGORY_UPDATE = 'blog-category:update';
export const BLOG_CATEGORY_DELETE = 'blog-category:delete';
```

Then add the rows and role grants to `scripts/seed-permissions-per-role.ts` and run:

```bash
npm run seed:permissions
```

> A permission string that is not a row in the `permissions` table and not granted to a role means
> **every request gets `403`** — the guard reads permissions from the *JWT*, which was minted from
> *database rows*. And because permissions are baked into a 30-minute token,
> **users must re-login after a permission change.**
>
> Note `blog-category` has no `:read` permission — its list and get are `@Public()`.

## Step 12 — The migration

```bash
npm run db:generate      # drizzle-kit diffs your schema files against the migration history
# ⚠ READ the generated SQL in src/infrastructure/databases/migrations/ before continuing
npm run db:migrate       # apply
```

> ### ⚠️ Before you run either command
> - **Only run `db:generate` in the service that owns the table.** auth-service owns the 7 RBAC
>   tables; core-service owns the other 61. Running it in the wrong repo emits `DROP COLUMN`
>   statements against the other service's columns. See
>   [`../README.md`](../README.md#51-a-shared-postgresql-database--and-a-rule-you-must-not-break).
> - **Always read the generated SQL.** drizzle-kit infers intent from a schema diff and sometimes
>   infers a drop-and-recreate where you wanted a rename.
> - **Never run `db:migrate` against production without a human.** core-service's own `CLAUDE.md`
>   states this as a hard rule. No CI pipeline runs migrations.
> - **`git pull` first, and never rename a migration.** Numbering has already collided — there are
>   two `0164_*.sql` files, disambiguated only by `meta/_journal.json`, so the file prefix and the
>   journal index are off by one from `0164` onward.

House convention: hand-editing the generated SQL to add `IF NOT EXISTS` for idempotency is common
and accepted. `breakpoints: false` in `drizzle.config.ts` means no `--> statement-breakpoint`
separators.

## Step 13 — Tests

Every use case gets a `.spec.ts`. The house style is a **hand-written fake implementing the full
port** — no `jest.mock`, no Nest `Test` module, plain constructor injection:

```ts
class MockBlogCategoryRepository implements IBlogCategoryRepositoryPort {
  private store = new Map<string, BlogCategory>();

  async save(category: BlogCategory): Promise<void> {
    this.store.set(category.id.getValue(), category);
  }
  async findByName(name: string): Promise<BlogCategory | null> {
    for (const cat of this.store.values()) {
      if (cat.name === name) return cat;
    }
    return null;
  }
  // … every port method implemented
}

describe('CreateBlogCategoryUseCase', () => {
  let useCase: CreateBlogCategoryUseCase;
  let repository: MockBlogCategoryRepository;

  beforeEach(() => {
    repository = new MockBlogCategoryRepository();
    useCase = new CreateBlogCategoryUseCase(repository);
  });

  it('should throw BlogCategoryAlreadyExistsException when the name is taken', async () => {
    await useCase.execute(baseCommand);
    await expect(useCase.execute(baseCommand)).rejects.toThrow(BlogCategoryAlreadyExistsException);
  });
});
```

Because use cases inject ports rather than concrete classes, this needs no DI container at all.

```bash
npm run lint      # eslint --fix
npm test          # jest
```

> **Specs are excluded from lint** (`**/*.spec.ts` is in `eslint.config.mjs` `ignores`) **and CI
> runs neither tests nor lint.** All 137 specs only ever run locally, so running them is on you.
